# real_daytime

## Introduction

**real_daytime** is a time-based environment system

Its current purpose is to control the day and night cycle of server areas using either:

- the local time of the computer running the server;
- or a custom timezone configured individually for each map.

Based on the current time, the system automatically determines the current phase of the day, changes the area's foreground, and exposes time, date, and weekday information through custom map properties.

The system also exposes the current time state through custom map properties. These properties can be read by other scripts, allowing the server to create events, NPC behaviors, shops, encounters, or other systems that depend on the current time, date, or weekday.

The system is designed to work independently for each area. This means different maps can use different timezones and therefore have different times and even different dates at the same moment.

## Map Custom Properties

The system uses two configuration properties and generates three runtime properties.

### Ambient_day_night

Type:

```text
String
```

This property defines how the day and night system behaves in the area.

Possible values:

```text
sync
cus
off
```

**FOR THE REAL TIME SYSTEM WORK, THIS PROPERTY MUST BE SET IN YOUR MAP AS EITHER SYNC,CUS OR OFF**

**IF Ambient_day_night DOES NOT EXIST OR CONTAINS AN INVALID VALUE, IT HAD NOT AFFECTED THE AREA IN ANY WAY.**

### sync

Uses the local time of the computer running the server.

Example:

```text
Ambient_day_night = sync
```

If the server machine is currently at:

```text
14:30
```

the area will also use that time.

This mode ignores `Ambient_timezone`.

### cus

Uses a custom timezone defined by `Ambient_timezone`.

Example:

```text
Ambient_day_night = cus
Ambient_timezone = -180
```

This allows each map to have an independent timezone based in original real time.

### off

Disables the day and night visual changes system for that area.

Example:

```text
Ambient_day_night = off
```

When off, the system generatetime properties but doesnt apply visual changes.

## Ambient_timezone

Type:

```text
Float
```

This property is used only when:

```text
Ambient_day_night = cus
```

The value represents the timezone offset in minutes relative to UTC.

Examples:

```text
UTC-3
Ambient_timezone = -180
```

```text
UTC
Ambient_timezone = 0
```

```text
UTC+5:30
Ambient_timezone = 330
```

```text
UTC+5:45
Ambient_timezone = 345
```

The accepted range is:

```text
-840 to +840
```

which represents:

```text
UTC-14 to UTC+14
```

If `cus` mode is enabled and `Ambient_timezone` is missing or invalid, the day and night system is disabled for that area.

## Day_time

This property is automatically generated by **real_daytime**.

It represents the current phase of the day.

Possible values:

```text
dawn
morning
afternoon
night
```

Current phase schedule:

```text
00:01-06:00 dawn
06:01-12:00 morning
12:01-18:00 afternoon
18:01-24:00 night
```

Example:

```text
Day_time = night
```

Another script can read it with:

```lua
local day_time = Net.get_area_custom_property(area_id, "Day_time")
```

This makes it possible to create systems that only work during certain periods of the day.

Example:

```lua
if day_time == "night" then
  -- night-only behavior
end
```

## Day_date

This property is automatically generated by **real_daytime**.

It stores the current date of the area.

Format:

```text
YYYY-MM-DD
```

Example:

```text
Day_date = 2026-10-17
```

Another script can read it with:

```lua
local day_date = Net.get_area_custom_property(area_id, "Day_date")
```

This property updates automatically when the date changes.

It also respects the timezone of the area, which means two different areas may have different dates at the same moment.

Example:

```text
Area A
Day_date = 2026-10-17
```

```text
Area B
Day_date = 2026-10-18
```

## Day_type

This property is automatically generated by **real_daytime**.

It stores the current weekday.

Possible values:

```text
sunday
monday
tuesday
wednesday
thursday
friday
saturday
```

Example:

```text
Day_type = saturday
```

Another script can read it with:

```lua
local day_type = Net.get_area_custom_property(area_id, "Day_type")
```

This property is updated whenever the current date changes.

## Using real_daytime for Server Events

One of the main purposes of **real_daytime** is to provide a shared time system that other scripts can use.

Instead of every script calculating time independently, they can simply read:

```text
Day_time
Day_date
Day_type
```

This makes it possible to build scheduled server content in a simple and consistent way.

## Events Based on Time of Day

A script can check `Day_time` to make something happen only during a specific phase.

Example:

```lua
local day_time = Net.get_area_custom_property(area_id, "Day_time")

if day_time == "night" then
  -- activate a night event
end
```

Possible uses include:

- NPCs that only appear at night;
- enemies that only spawn in the morning;
- shops that close during the night;
- special music during dawn;
- nighttime decorations;
- different encounters depending on the time of day;
- doors or areas that only open during certain phases.

Example:

```lua
if day_time == "dawn" then
  -- spawn a special NPC
end
```

## Events Based on Weekday

A script can use `Day_type` to create events that only occur on specific days of the week.

Example:

```lua
local day_type = Net.get_area_custom_property(area_id, "Day_type")

if day_type == "sunday" then
  -- sunday-only event
end
```

Possible uses include:

- weekend events;
- shops that only open on certain weekdays;
- weekly bosses;
- rotating NPCs;
- scheduled tournaments;
- weekly rewards;
- different quests depending on the day.

Example:

```lua
if day_type == "friday" then
  -- friday event
end
```

## Events Based on Specific Dates

A script can use `Day_date` to create events that only happen on a specific calendar date.

Example:

```lua
local day_date = Net.get_area_custom_property(area_id, "Day_date")

if day_date == "2026-12-25" then
  -- christmas event
end
```

Possible uses include:

- holiday events;
- anniversaries;
- server launch celebrations;
- limited-time bosses;
- seasonal decorations;
- special rewards;
- one-day events.

Example:

```lua
if day_date == "2026-10-31" then
  -- halloween event
end
```

## Combining Time, Date, and Weekday

The generated properties can also be combined.

For example, a server event could only happen:

```text
on Saturday
at night
```

Example:

```lua
local day_time = Net.get_area_custom_property(area_id, "Day_time")
local day_type = Net.get_area_custom_property(area_id, "Day_type")

if day_type == "saturday" and day_time == "night" then
  -- saturday night event
end
```

A more specific event could happen only:

```text
on a specific date
during the night
```

Example:

```lua
local day_time = Net.get_area_custom_property(area_id, "Day_time")
local day_date = Net.get_area_custom_property(area_id, "Day_date")

if day_date == "2026-10-31" and day_time == "night" then
  -- halloween night event
end
```

You can also combine all three:

```lua
local day_time = Net.get_area_custom_property(area_id, "Day_time")
local day_date = Net.get_area_custom_property(area_id, "Day_date")
local day_type = Net.get_area_custom_property(area_id, "Day_type")

if day_date == "2026-12-25"
    and day_type == "friday"
    and day_time == "night" then
  -- special christmas night event
end
```

## Different Timezones for Different Areas

Because every area can use its own `Ambient_timezone`, different maps can have different local times.

Example:

```text
Area A
Ambient_day_night = cus
Ambient_timezone = -180
```

```text
Area B
Ambient_day_night = cus
Ambient_timezone = 330
```

At the same real-world moment, Area A could have:

```text
Day_time = afternoon
Day_date = 2026-10-17
Day_type = saturday
```

while Area B could have:

```text
Day_time = night
Day_date = 2026-10-18
Day_type = sunday
```

This can be useful for servers with regions, countries, planets, dimensions, or locations that are meant to operate in different timezones.

## Runtime Timezone Changes

The timezone of an area can also be changed while the server is running.

After changing:

```text
Ambient_timezone
```

or:

```text
Ambient_day_night
```

call:

```lua
real_daytime.refresh_area(area_id)
```

Example:

```lua
Net.set_area_custom_property(area_id, "Ambient_timezone", 330)

real_daytime.refresh_area(area_id)
```

The system will immediately recalculate:

```text
Day_time
Day_date
Day_type
```

and apply the correct foreground for the new local time.

This makes it possible to create future Time_Manager interfaces that allow administrators to control area time settings directly from an in-game UI.

## Summary

**real_daytime** provides two configuration properties:

```text
Ambient_day_night
Ambient_timezone
```

and automatically generates three time-state properties:

```text
Day_time
Day_date
Day_type
```

Together, these properties allow other scripts to create content based on:

- the current phase of the day;
- the current date;
- the current weekday;
- the timezone of each individual area.

This makes **real_daytime** useful not only as a visual day and night system, but also as a general time foundation for server events, NPC schedules, shops, encounters, holidays, weekly activities, limited events, and future HP_Manager systems.
